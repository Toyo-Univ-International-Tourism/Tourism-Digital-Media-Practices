① 企画→ ② ツアー制作（制作ソフト）→ ③ 公開設定・共有→ ④ 紹介ページ制作（AI活用）→ ⑤ GitHubで公開

要件

作るもの・必須要件

バーチャルツアー（制作ソフト）

  • 2シーン以上（3シーン推奨）
  • タイトルがある
  • （A/B）ホットスポットで移動できる
  • 公開設定して見られる状態

紹介ページ（自作・3ファイル）

  • 3ファイル構成（html/css/js）
  • タイトル・説明がある
  • ボタン等でツアーに到達できる
  • JavaScriptの動きが1つ以上
自由なところ（好きにやってOK） ・ツアーは 紹介ページに埋め込んでも、ボタンでリンクしてもどちらでもよい（押せばしっかり見られればOK）
・紹介ページのレイアウトは自由（縦長でなくてよい）。デザインは自分の企画に合わせて
※ 公開：最後に GitHub Pages でURL公開できていること。
企画

制作タイプを選ぶ（素材で決まる）

A キャンパスツアー型

素材：白山キャンパス（当日撮影）

つながり：○ 歩いて移動

機能：360ツアー

B 観光プロモ型

素材：宮古島ビーチ（提供）

つながり：△ 数シーン

機能：360ツアー

C ギャラリー型

素材：フリー素材30種から選ぶ

特徴：テーマ別の"展示"（各写真は独立・移動でつながらない）

見せ方：360フォトを作り、紹介ページにサムネ一覧→クリックで開く

  • 迷ったら：歩いて移動＝A／1か所をじっくり＝B／いろんな景色を集めて並べる＝C。まずは3シーン（3枚）で。
  • 企画（誰に・何を・どの順で）は配布の企画シートに記入 → 教員に見せてから制作へ。
※ ギャラリー型＝バラバラな360°写真を"作品集"のように見せる型。歩いて移動はできないので、紹介ページにサムネイルを並べ、押すと各写真が開く形にする（サムネ画像は制作ソフトのSNSキットで書き出せる）。

作る

公開設定 → 共有（URL／埋め込み）★

制作ソフト上で、作った作品を公開設定して共有情報を取得します。紹介ページからツアーに行けるように、両方コピーしておくと安心。

① 制作ソフトで公開設定→ ② 「共有」を開く→ ③ リンクURL と 埋め込みコードをコピー

A：リンクURL（ボタン用）

https://…/v/xxxx ← ツアー https://…/s/xxxx ← 360フォト

B：埋め込みコード（貼る用）

<iframe src="…?embed=1" …></iframe>
どちらを使う？紹介ページに埋め込むならB、ボタンで飛ばすならA。今日はどちらでもOK。コピーボタンの文字列をそのまま使う（手打ちしない）。

作る

ツアーへの導線（2通り・どちらでもOK）

方法1：ボタンでリンク（手軽）

<a href="https://…/v/xxxx" target="_blank"> <button>ツアーを見る</button> </a>

押すと別タブでツアーが開く。まずはこれで十分。

方法2：ページに埋め込み

<!-- 共有→埋め込みのコードを貼る --> <iframe src="…?embed=1" width="100%" height="480" …></iframe>

ページ内でそのまま360°が回る。

大事なのはここだけ「ボタン等を押したら、しっかりしたツアーが見られる」こと。埋め込むか飛ばすかは自由。
※ C ギャラリー型：サムネイル画像に各360フォトのリンクを付けて一覧にする。
作る

プロンプトの型（コピーして使う）

講義第4部の5要素＋技法を全部入れた"良いプロンプト"。［　］を自分の企画に置きかえる。

紹介ページを作ってもらうプロンプトあなたは初心者にやさしいWeb制作の先生です。〔役割〕 ［観光地名］を紹介し、バーチャルツアーの入口となる紹介ページを作ってください。〔目的〕 【構成】index.html / style.css / script.js の3ファイルに分ける。CSS・JSは外部ファイルで読み込み、HTMLへの直書きは禁止。〔構造化・禁止〕 【内容】大見出し「［キャッチコピー］」＋一言／説明文3行／サムネ3枚（画像は https://picsum.photos で代用）／「ツアーを見る」ボタン〔具体・例示〕 【デザイン】白背景／アクセント色 ［#4A9FD8］／余白は広め／日本語ゴシック〔具体〕 【動き】ボタンを押すとツアー（下部のiframe）が表示される〔タスク〕 初心者向けに日本語コメントを付け、3ファイルをコード全体で出してください。〔出力形式〕

入っている要素・技法

役割／目的／タスク／制約（＋禁止）／出力形式 ＋ 構造化【】・具体化・例示

できたら追いプロンプト

「余白をもっと広く」→「JSでフェードイン」→「スマホ対応」…1回1テーマ

※ サムネ画像は placeholder（例：picsum.photos）でもよいが、制作ソフトのSNSキットでサムネ画像や切り出し画像を書き出して images/ に置くと本物らしくなる。詳しい技法は講義「第4部 プロンプトエンジニアリング」。
作る

AIの使い方（Web版Claudeでの進め方）

ブラウザのClaudeは「対話 → コードをコピー → VS Codeに貼る」の繰り返し。この流れで進める。

① 型どおり頼む→ ② 3ファイルをコピペ→ ③ Go Liveで確認→ ④ 直す所を追いプロンプト↻

Web版Claudeのコツ

  • 最初のプロンプトを作り込む（前ページの型）。3ファイルをまとめて出させる
  • 無料版はメッセージ回数に上限。小出しにしすぎず、質問はまとめて
  • 直す時は「どのファイルの・どこを・どうしたいか」を具体的に。1回1テーマ
直したい時のテンプレこのコードが思ったとおり動きません。原因と直し方を初心者向けに教えて。 ・やりたいこと：（例）ボタンでツアーを開きたい ・エラー：（F12→Consoleの赤い文） ・コード：（動かない部分）
※ 出てきたコードは丸写しにせず、読んで自分のものに直す（自分で説明できること）。個人情報は入力しない。
公開する

GitHub で公開する（1日目と同じ手順）

公開のやり方は1日目と同じ。共有リポジトリの 2026 フォルダに、作品フォルダごとアップロードする。

手順やること
①共有リポジトリ Tourism-Digital-Media-Practices を開く
②2026 フォルダを開き、Add file → Upload files を選ぶ
③今日の作品フォルダごとドラッグ＆ドロップ（空フォルダは作れないのでまとめて）
④Commit changes をクリック
⑤公開URLを開いて 表示・ツアーへの導線・JSの動き を確認 → 提出

※ 画面つきの詳しい手順は 1日目「Webコーディング体験」スライドを参照。公開直後は数分ラグあり（404でも待つ）。

まとめ ― 実習の合言葉

  • 両方を完成させる ― ツアーも紹介ページも "動く状態" でゴール
  • 小さく作って確かめる ― 1つ頼む → Go Liveで確認 → 次へ
  • ツアーへの導線は自由 ― 埋め込み or ボタン、押せば見られればOK
  • レイアウトは自由 ― 企画に合う形で作る
  • 丸写ししない ― 自分で説明できる状態に
