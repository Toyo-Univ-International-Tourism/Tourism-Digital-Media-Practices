課題書 ― バーチャルツアー＆紹介ページ制作

観光デジタルメディア演習（2日目）／ 制作は個人単位 ／ 提出：公開URL
🎯 ゴール：自分で企画したバーチャルツアーと、その入口となる紹介ページを作り、GitHubで公開する。
紹介ページ（自分でコーディング）→ ボタン等で →バーチャルツアー（制作ソフトで制作）

1. 作るもの（2つ）

① バーチャルツアー

制作ソフトで360°作品を作る。素材で制作タイプが決まる（下表）。

② 紹介ページ（入口）

1日目に学んだ HTML / CSS / JavaScript で自作。3ファイル（index.html / style.css / script.js）。

2. 制作タイプ（1つ選ぶ）

タイプ素材特徴・見せ方
Aキャンパスツアー型白山キャンパス（当日撮影）歩いて移動できる。ホットスポットでシーンをつなぐ（360ツアー）
B観光プロモ型宮古島ビーチ（提供素材）数シーンで魅力を伝える（360ツアー）
Cギャラリー型フリー素材パノラマ30種場所はつながらない → 紹介ページにサムネイル一覧で見せる（360フォト。サムネは制作ソフトのSNSキットで書き出せる）

3. 必須要件（これが揃えば合格）

バーチャルツアー

  • 2シーン以上（3シーン推奨）
  • タイトルがある
  • （A/B）ホットスポットで移動できる
  • 公開設定して見られる状態

紹介ページ（自作3ファイル）

  • 3ファイル構成
  • タイトル・説明がある
  • ボタン等でツアーに到達できる
  • JavaScriptの動きが1つ以上
  • GitHub Pages で公開され、URLで誰でも見られる
■ 自由なところ（好きにやってOK）
・ツアーは 紹介ページに埋め込んでも、ボタンでリンクしてもどちらでもよい（押せばしっかりしたツアーが見られればOK）
・紹介ページの レイアウトは自由（縦長でなくてよい）。デザインは自分の企画に合わせて自由に。
※ 時間が足りないときは シーン数を減らして完成を優先。「ツアーと紹介ページの両方が中途半端」が一番もったいない。

4. 進め方

① 企画→ ② ツアー制作（制作ソフト）→ ③ 公開設定・共有→ ④ 紹介ページ制作（AI活用）→ ⑤ GitHubで公開
  1. 企画：制作タイプを選び、配布の「企画シート」を書く（誰に・何を・どの順で／シーン構成）。
  2. ツアー制作：制作ソフトで素材を取り込み、作品を新規作成してシーンを配置。A/Bは矢印（ホットスポット）で移動を作る。タイトルをつける。
  3. 公開設定・共有：制作ソフト上で作品を公開設定し、「共有」から リンクURL と 埋め込みコード をコピーしておく。
  4. 紹介ページ制作：AIに型どおり頼んで3ファイルをまとめて作り、Go Live で確認しながら仕上げる。ツアーへの導線（ボタン or 埋め込み）を入れる。
  5. 公開：1日目と同じ手順で、共有リポジトリの 2026 フォルダに作品フォルダごとアップロード（GitHub Pages で公開）。URLで動作確認 → 提出。

5. ツアーへの導線（どちらでもOK）

方法1：ボタンでリンク（手軽）

<a href="https://…/v/xxxx" target="_blank"><button>ツアーを見る</button></a>

押すと別タブでツアーが開く。まずはこれで十分。

方法2：ページに埋め込み

制作ソフトの「共有→埋め込み」でコピーした <iframe …?embed=1> を紹介ページに貼る。

ページ内でそのまま360°が回る。

6. AIの使い方（プロンプトの型）

良いプロンプトは ①役割 ②目的 ③タスク ④制約（＋禁止）⑤出力形式 の5要素で組み立てる（講義 第4部）。具体化・否定制約・段階化の技法も使う。

下の型の ［　］ を自分の企画に置きかえて使う：

あなたはWeb制作の先生です〔役割〕。［観光地名］を紹介し、バーチャルツアーの入口となる紹介ページを作ってください〔目的〕。 【構成】html/css/jsの3ファイル・外部ファイル読み込み・直書き禁止〔制約〕　【内容】見出し「［キャッチ］」／説明3行／サムネ3枚（picsum.photosで代用）／「ツアーを見る」ボタン〔具体・例示〕　【デザイン】白背景／アクセント［#色］／余白広め〔具体〕 初心者向けにコメントを付け、3ファイルをコード全体で出してください〔出力形式〕。

進め方3つ：①型どおりまとめて頼む（3ファイル）②すぐ確かめる（Go Live）③エラーは渡す（Consoleの赤い文をコピーして聞く）。できたら追いプロンプトで1回1テーマずつ改善。

注意：丸写しにせず読んで直す（自分で説明できること）。個人情報は入力しない。無料版は回数制限あり＝質問はまとめて。

7. 提出物

  • 公開された GitHub Pages のURL（紹介ページ → ツアーまで動くこと）
  • 作業フォルダ構成：index.html / style.css / script.js（＋使う画像は images/）

8. 評価の観点

「3. 必須要件」がひととおり満たされていることが基本。加えて、次の点を見ます。

  • 企画：想定閲覧者が明確で、制作タイプと内容が合っているか
  • 完成度：ツアー・紹介ページ・公開が通しで動くか
  • 自分で説明できるか：AIの出力を丸写しにせず、内容を理解しているか
  • 工夫：デザインや作り込みの工夫（加点）
※ 完璧さよりも「両方を完成させて公開する」ことを優先。困ったら教員を呼んでください。
